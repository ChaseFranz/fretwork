# 05. Data model v2

**Status:** Ready after 00

**Effort:** L, dominated by the JavaScript loading contract (every module that reads `DATA` today changes) and the page suites that must prove it, not by the Python side.

**Depends on:** 00 (fixes-first: publish must refuse a mismatched cache and xlsx, and a drums code must resolve to "no graph" rather than crash, because this section reuses that lookup). Section 00's three page routes (`about.html`, `404.html`, `robots.txt`) fold into the `files` dict lookup here rather than stacking on it; what survives from 00 is the 404 body and the no-graph lookup guard.

## Goal

Split the one 1.78 MB `index.html` into a 12 KB entry page plus content-hashed, immutable files: per-sheet row JSON under `data/`, one JS bundle, one CSS file, Bootstrap and the favicon under `static/`, and a per-chart curve JSON under `graph/` beside the PNG it will later replace. Give every song a stable identity (`SongKey`) that survives a re-download, stamp browser preferences with a version so a changed default can be re-applied, and give `deploy.py` three cache classes so an entry page is always fresh and everything it names is cached for a year. `serve.py` serves the same bytes from memory with the same cache classes. Every later section builds on the shapes named under "Data and interfaces".

## Why

- `site/Local/index.html` is 1,780,936 bytes of which the `#fw-boot` island is 1,778,082 (99.8%); the page markup outside it is 2,854 bytes. Every visit downloads the whole spreadsheet again because the page is deployed `no-cache` (`deploy.py:58,191`), and so are the 17 ES modules, so a repeat visit is 21 conditional requests before the first row paints.
- A cold view is 21 requests today (index, bootstrap, app.css, favicon, 17 modules). This design makes it 6 before the page is usable plus 2 idle prefetches, and a repeat visit drops from 21 revalidations to one (`index.html`). The per-view counts stand on their own; the account's CloudFront request allowance is not known from the code (see Out of scope).
- Graphs are 11,904 PNGs, 2,188,837,822 bytes, 0.12 s each to render; the same information as raw window counts plus the header numbers is 47.6 MB (about 6.5 MB gzipped) and 4.6 s for the whole library. Section 06 draws from it; this section publishes it.
- Codes are path hashes (`functions/cache.py:61-63`): a pack re-downloaded into a different folder changes every code, so nothing today can say "this is the same song". Sections 03, 07 and 10 need a key that does not move.
- `labels.DEFAULT_HIDDEN` is only honoured on a first visit (`state.js:11-16` takes the saved list verbatim), so a column added and meant to be hidden (this section adds `SongKey`) would appear for every returning visitor.

## Design

**1. Row data leaves the page.** `boot['data']` becomes a manifest `{sheet: {file, rows, columns}}`; the rows go to `data/<slug>.<hash8>.json` holding exactly what `frames_payload` emits today for that sheet, `{columns, rows}`, serialised with `json.dumps(sheet, separators=(',', ':'), ensure_ascii=False).encode('utf-8')`. `hash8` is the first 8 hex digits of SHA-1 over the file bytes. The slug is the sheet name lower-cased with every run of characters outside `[a-z0-9]` replaced by one `-` and leading or trailing `-` stripped; publish raises if two sheets slug alike or a slug is empty. Sheet names come from `instruments.SHEET_GROUPS` keys through analyze's 31-character Excel truncation (`analyze.py:209`), so today's slugs are `guitar`, `bass`, `keys`, and `drums` when section 11 lands. The `<` escape is not applied to these files: `boot.py:35` exists because the island sits inside a `<script>` element, where `</script>` in a title would end the element; a file fetched with `fetch()` and parsed by `response.json()` never enters an HTML or script context, and a browser that navigates to it directly renders `application/json` as text. The manifest, sheet names and column names still go through the island and keep the escape. Old hashed files are pruned exactly as `static/` is pruned today: anything under `data/` this publish did not write is deleted (`prune_page`), and `sync --delete` then removes it from the bucket. `page.ROBOTS` gains `Disallow: /data/` for the same reason it disallows `/graph/`: three files that change every publish are not worth a crawl. Rejected: keeping rows inline and gzipping harder, because a repeat visit would still download 400 KB; one file for all sheets, because the first paint would wait for Guitar's 293 KB even on the Keys sheet, whereas the idle prefetch fetches the other sheets only after the page is usable and never under Save-Data.

**2. Loading contract.** The island keeps everything except rows, so `boot.js` still parses synchronously and every other module still gets its constants at evaluation. The rows live in a registry `state.data` (`{sheet: {columns, rows}}`, empty at start) filled by `loadSheet(name)` in a new `load.js`, which fetches `SHEETS[name].file`, memoises one in-flight promise per sheet, and rejects on a non-2xx status. `cols()` reads `SHEETS[state.sheet].columns` from the manifest, so column geometry, the chooser, the sort fallback and the URL reader all work before any row arrives; `rowsAll()` returns `[]` for an unloaded sheet and `draw()` then paints a single loading row (class `empty loading`, so the widths stylesheet skips it) and puts `Loading 6610 charts...` in `#count`. `main.js` paints header, chips and controls synchronously, then `loadSheet(state.sheet)`, then re-renders, opens a shared graph, and asks for the other sheets in `requestIdleCallback` (falling back to `setTimeout(fn, 2000)`, and not at all when `navigator.connection.saveData` is true) so a later sheet click, and a later deploy that deletes the old hashed file, both hit the browser cache. A shared `?code=` survives the loading state: `main.js` sets `state.graph` before the first `render()`, because `draw()` calls `writeUrl()` (`table.js:88`) and `params()` would otherwise rewrite the address bar without the code 250 ms later. `format.decimals()` memoises only when the sheet's rows are present, otherwise it returns 0 without memoising. `readUrl()` validates `?sheet=` against `SHEETS`, and when a link names a `code` without a sheet it picks the sheet from the code's instrument letter through a `sheetOfCode` table in the boot payload, so `?code=...XB` opens Bass with a filled heading rather than Guitar with a blank one. A failed fetch shows `UI.load_failed` with a reload link in the loading row; a 404 after a deploy is the expected reason. Rejected: top-level `await` in `boot.js`, because it blocks every module and the first paint behind the largest file; a synchronous XHR, obviously; opening the shared graph before the rows arrive, because `openGraph` captures the heading once and the image `onload` would paint the stale blank heading over a later refresh.

**3. One JS bundle, hashed assets.** Measured above, the 17 modules satisfy every precondition for concatenation, so `web/bundler.py` (new, stdlib only) produces `static/app.<hash8>.js`: parse each module, allow only `import { a, b } from "./x.js";` (possibly spanning lines) and `export` prefixed to `const`, `let`, `function` or `class` declarations, collect every top-level declaration, fail loudly on any other import or export form, on an imported name the target does not export, on a top-level name declared in two modules, or on an import cycle; order modules by depth-first post-order from `js/main.js`; emit each module's source with its import statements deleted and the `export ` prefix removed, under a `// ---- <file>` banner. Nothing else is rewritten: no minification, no renaming, so `rich()` in `dom.js`, `rich_text()`'s twin, and the `"https://www.youtube-nocookie.com"` origin in `overlay.js:106` survive byte for byte, and a diff of the bundle against the sources is line-for-line. The bundle is loaded with `<script type="module">`, which keeps strict mode and deferred execution, and ES module evaluation order is the same post-order the bundler emits, so module-level side effects run in the order they run today. `app.css`, `favicon.svg` and Bootstrap are hashed the same way and all live under `static/` (`static/app.<h>.css`, `static/favicon.<h>.svg`, `static/bootstrap.<h>.css`), which makes "everything under `static/` and `data/` is immutable" a rule with no exceptions and removes the top-level `bootstrap.css` and its special route. `index.html` gains `__FAVICON__`, `__STYLES__` and `__SCRIPT__` placeholders; `about.html` and `404.html` gain `__FAVICON__` (root-absolute in the 404, as its other links are). Requests per cold view: 21 today become 6 before the page is usable (index, bootstrap, app.css, favicon, app.js, the default sheet's JSON) plus 2 idle prefetches, 8 in all; a repeat visit is 1 request instead of 21. Rejected: (a) 17 hashed modules with `modulepreload`, because hashing a module changes the specifier inside every importer, which needs a fixed-point rewrite pass, and still costs 17 requests and a 3 to 4 level import waterfall on every cold view; esbuild or rollup, because the repo has no Node toolchain in its requirements and CLAUDE.md keeps the web layer dependency-free (the Node on this box is used only to `--check` the output); a minifier, because 14.7 KB gzipped is not worth losing the string-literal guarantees.

**4. Deploy classes.** Three classes, each its own sync: entry points (`index.html`, `about.html`, `404.html`, `robots.txt`, any future page) `no-cache`; hashed immutable files (`static/`, `data/`) `public, max-age=31536000, immutable`; graphs (`graph/`) `public, max-age=604800` as today. The class of a name is decided by one function, `assets.cache_class(name)`, which serve uses too. Order: `graph/` first as today, then `static/` and `data/` uploaded without `--delete`, then the entry points with `--delete` and the three directories excluded, then the CloudFront invalidation, then `aws cloudfront wait invalidation-completed` on the id the create call returned, then `static/` and `data/` again with `--delete`, which uploads nothing and removes the previous generation. A page in flight therefore always finds what it names: the new files exist before the new page, and the old files outlive the old page until CloudFront confirms the invalidation; the idle prefetch covers a tab that was open across the deploy. A class whose local directory is absent is skipped on both its passes, printing `skipped: no <dir>/ locally`, so a dry run against a bundle from before this section still prints a plan. `verify()` stops naming files and instead takes the first local match of one glob per pattern and checks both `ContentType` and `CacheControl`. Rejected: keeping the previous N hashed generations in a manifest, because the deferred delete plus the wait closes the window without bookkeeping; deleting immediately after the invalidation request, because `create-invalidation` returns before any edge has dropped the old page.

**5. Stable song key.** `SongKey` is the first 12 hex digits of SHA-1 over the sorted tuples `(instrument, level, time_ms bytes, lanes bytes)` of every five-fret stream of a song (instruments in `instruments.SONG_KEY_INSTRUMENTS`, the five 5-fret keys, fixed forever so the key does not move when drums are scored). Computed once per song in build (0.04 s for 1,758 songs), stored in the cache song dict as `song_key`, emitted by analyze as a hidden xlsx column, and shown on the page only through the column chooser. Two folders with identical charts share a key (10 pairs in the Local library); a re-download of a pack to a new folder keeps its keys while every `Code` changes. `Code` stays the graph file name, the row click key and the report-form key. Rejected: a key over title and artist, which over-merges about eleven to one (115 title-and-artist groups against 10 content groups on the same cache); a key over one instrument, which would merge songs that differ only on bass.

**6. Curve JSON.** `graph/<code>.json` holds the raw window counts, not the smoothed curves, plus a `head` object with the numbers the PNG header prints, so section 06 can draw the graph and its heading from one file and the row. The client re-smooths with the exact algorithm: a smoothing constant change is a seconds-long rewrite of the JSON, never a PNG re-render, and a change to the smoothing algorithm is a client change with a `v` bump. Measured with the shape below, `gzip.compress` level 6: 4,004 bytes (670 gzipped) for 72933816XG, 8,474 (1,704) for 10145439XG, 47,613,377 bytes for all 11,904 charts (mean 4,000; about 6.5 MB gzipped, estimated from every 40th chart) in 4.6 s for the whole library, against 2,188,837,822 bytes of PNGs. Its fingerprint covers the note bytes, the Expert note bytes, `source_format`, the difficulty block and the window and smoothing constants, never the theme or the meta, so a theme edit or a `song.ini` retitle rewrites no JSON. It is tracked in its own manifest, `graph/curves-manifest.json`, so `graph/manifest.json` keeps today's `{code: sha1}` shape and a rollback to the previous commit re-renders nothing. Section 06 owns the renderer; this section publishes the file beside the PNG and serves it locally. Rejected: a head with the original song.ini tier from the backup CSV, because the row's `Difficulty` column is the same value except after a `--diff-mode` write, which the hosted pipeline never runs; a head with `Charter`, `Release` or the title, because the row has them and meta must stay out of the fingerprint.

**7. Preference version.** `labels.PREFS_VERSION` reaches the page through the boot payload; `state.js` compares it with `localStorage['fw.v']` before reading `fw.hidden`, removes `fw.hidden` when the stored stamp is older (an absent stamp counts as 0) and writes the new stamp. Order and widths are kept: they are the viewer's, and a stale entry in either is harmless (`ordered()` filters unknown columns, widths apply by name). It starts at 1 in this section because `SongKey` joins `DEFAULT_HIDDEN`.

**8. Serve parity.** `page.build()` returns one `files` dict of everything the site is, `{relative name: bytes}`; publish writes it and serve serves it from `'/' + name`, with content types from one extension table and `Cache-Control` from `assets.cache_class`, so the two cache behaviours this section exists to deliver are observable against `serve.py`, not only after a deploy. The handler's only computed lookups are `path in self.server.files` and the `graph/` branch, so no key derives from the request path. The `/bootstrap.css` route goes away with the file. `index.html` differs between serve and publish by the `public` flag alone (title, strapline, canonical and OG tags, `web/page.py:144-151`); every other file is byte-identical.

## Data and interfaces

**Site folder (`SITE_DIR/<header>/`)**, and `deploy.BUNDLE_TOP`:

| Path | Class | Cache-Control | Content-Type |
|---|---|---|---|

`deploy.BUNDLE_TOP` is the entry pages (`index.html`, `404.html`, `about.html`, `robots.txt`, plus any document page 03 or 12 has added by then) and the three directories `static`, `data`, `graph`; `bootstrap.css` leaves. `deploy.REQUIRED` stays `('index.html', 'graph/manifest.json')`. `bundle.prune_page` sweeps `static/`, `data/` and the four named files, and removes a directory it has emptied. `static/bootstrap.<hash8>.css` is absent under `--no-bootstrap`, when `FALLBACK_CSS` is inlined as today. `page.ROBOTS` becomes `User-agent: *`, `Allow: /`, `Allow: /graph/10145439XG.png`, `Disallow: /graph/`, `Disallow: /data/`.

`hash8` everywhere: `hashlib.sha1(file_bytes).hexdigest()[:8]`, computed on the final bytes of the file that is written. Slug: `re.sub(r'[^a-z0-9]+', '-', name.lower()).strip('-')`, non-empty and unique or publish raises `ValueError`.

**`web/assets` tables** (one place, used by the handler, by `write_page` and by deploy): `CONTENT_TYPES = {'.html': 'text/html; charset=utf-8', '.txt': 'text/plain; charset=utf-8', '.js': 'text/javascript; charset=utf-8', '.css': 'text/css; charset=utf-8', '.svg': 'image/svg+xml', '.json': 'application/json', '.png': 'image/png'}`; `CACHE_PAGE = 'no-cache'`, `CACHE_IMMUTABLE = 'public, max-age=31536000, immutable'`, `CACHE_GRAPHS = 'public, max-age=604800'`, `IMMUTABLE_DIRS = ('static', 'data')`; `cache_class(name)` strips one leading `/` and returns `CACHE_IMMUTABLE` under an `IMMUTABLE_DIRS` prefix, `CACHE_GRAPHS` under `graph/`, else `CACHE_PAGE`. `deploy.py` imports these from `web.assets` rather than restating them.

**`page.build(header, xlsx_path, bootstrap_css, public=False) -> Built`**, a namedtuple `(xlsx_path, sheets, total, files)` where `files` is `{relative_name: bytes}` covering every entry and immutable file above (never `graph/`). `publish.publish` passes `files` to `bundle.write_page(out_dir, files)`; `serve.serve` passes `{'/' + name: data for name, data in files.items()}` to `MetricsServer(port, files, graphs)`. Per-sheet JSON bytes, the bundle and the hashed names are all produced inside `build()` so the two entry points cannot disagree.

**Curve JSON** (`graph/<code>.json`):

```json
{"v":1,"step":250,"window":1000,"tau":2000,"n":960,
 "head":{"N":4.265,"V":2.6148,"COV":1.4228,"D":15.8675,"RemapDiff":2,"CalcTier":2,"source":"mid"},
 "win":[0,1,3,...],"var":[0,1,2,...]}
```

`step`, `window` and `tau` are written as `int(density.STEP_MS)`, `int(density.WINDOW_MS)` and `int(curves.TAU_MS)`, all exact integers today (the constants are floats and `json.dumps` would otherwise write `250.0`); the fingerprint hashes the raw constants. `win[i]` = notes in `[i*step, i*step+window)` ms, `var[i]` = fret changes in the same window, both non-negative integers straight from `density.window_arrays` (`raw_nps_samples`, `raw_vps_samples`); `n = floor(last_note_ms / step) + 1` and both arrays have length `n`; the time axis is implied, `t_ms = i * step`. `head` is `difficulty.entry_difficulty(entry)` with `N`, `V`, `COV`, `D` rounded to 4 places, `RemapDiff` and `CalcTier` as integers or `null`, plus `source` = `entry['source_format']`; it is what the PNG header prints minus what the row already has. Client reconstruction, which section 06 implements: `rate = count / (window / 1000)`; `decay = Math.exp(-step / tau)`, `gain = 1 - decay`; forward pass `acc = acc * decay + rate * gain` from `acc = 0`, then the same pass over the reversed result, reversed back; `d = Math.sqrt(nps * vps)`. That is `curves._ema_forward` and `_ema_curve` operation for operation in IEEE doubles, so the plotted curve matches the PNG's to within a libm ulp of `exp`. `v` is the format version; a reader rejects any other value. Serialised compact, no whitespace. Fingerprint: `sha1(pickle((1, time_ms bytes, lanes bytes, expert time_ms bytes or b'', expert lanes bytes or b'', source_format, repr(entry_difficulty(entry)), WINDOW_MS, STEP_MS, TAU_MS)))`; recorded in `graph/curves-manifest.json`, `{code: sha1}` sorted, the same shape as `manifest.json`.

## Risks and gotchas

- `IMMUTABLE_DIRS` must never be synced while `static/` holds unhashed names: the pass stamps `max-age=31536000, immutable` on whatever it uploads, and a `main.js` pinned for a year under its fixed name cannot be un-pinned from the server side. That is why step 4 lands after step 2 and why no deploy happens in between. If `--set-headers` is ever run against a bucket in the old layout, the same hazard applies.
- The leaderboards userscript (`fretladder-leaderboards.user.js:104-133` (the Tampermonkey prototype kept beside the repo, at `../fretladder-leaderboards.user.js`), untracked) reads rows out of the `#fw-boot` island, both on fretladder itself and from a daily download of `index.html`. After this section `boot.data` is a manifest with no rows, so `compactRows` throws on `sheet.rows` and the script fails silently. It must read the manifest and fetch `boot.data[sheet].file` relative to the page origin for each sheet; its other hooks (`#modal .mhead`, the aria-label ending in the code, the column names, `?q=&code=`) are untouched. See Out of scope.
- The bundler is a whitelist. The first module that uses `export {`, `import * as`, a renamed import or a dynamic `import()` fails publish with a message naming the line, which is the intended behaviour; the fix is to write the plain form, not to extend the bundler.
- Module scope becomes one scope. Two modules declaring the same top-level name is caught, but a top-level `let` in one module shadowed by a function parameter in another is legal in both worlds and needs no care. What does change: a module-level `const` referenced by a function in an earlier-ordered module is fine at call time, but a module-level statement in an earlier module that calls into a later module would throw `ReferenceError` in the bundle where it would have worked as a module cycle. The cycle check makes that impossible today.
- `requestIdleCallback` is absent in Safari; the `setTimeout` fallback is the contract, not a nicety. The Save-Data gate means a viewer who asked for less data gets no prefetch and pays one fetch per sheet click instead.
- A tab left open across a deploy holds an old manifest. The idle prefetch means every sheet is already in its cache; if it was not (the tab was opened with the network throttled, under Save-Data, or storage cleared), the click shows `load_failed` with a reload link. Do not add an automatic reload: a page that reloads itself while a viewer types in the search box is worse than one that asks.
- `create-invalidation` returns before the edges have dropped the old page; the `wait` is what makes the deferred delete safe, and a deploy that dies between the invalidation and the deletes leaves both generations in the bucket, which is safe and is cleaned by the next deploy.
- `index.html` is `no-cache`, not `no-store`: a viewer with a cached copy and no network sees the old page and its old hashed files come from cache too, which is correct.
- Chrome ignores the `immutable` token but treats `max-age=31536000` on a subresource as fresh across normal reloads; Firefox and Safari honour the token. Either way a repeat visit makes one request.
- `aws s3 sync` derives `Content-Type` from the system `mimetypes` table on upload; `.json` gives `application/json` and `.svg` `image/svg+xml` on every platform tried, but `verify()` exists because that has been wrong before, and now it checks the cache class as well.
- The `SongKey` hashes float64 milliseconds. Any change to `parsers/timing.py`, or a parser producing a different tick-to-ms rounding, changes every key in the next build; after such a change the rebuild gets a hand-written `[[change]]` entry in `packs.toml` (section 03) saying the song keys moved and older `?song=` links stop resolving, and section 10 must not persist keys across builds.
- `analyze.COLUMN_ORDER` grows by one column, so a spreadsheet consumer that reads by position moves; nothing in the repo does, and the web layer reads by name.
- `song_row` (`analyze.py:45`) takes `code, meta, notes` and the anchors and never sees the song dict, so `song_key` arrives as a new keyword parameter from the call at `analyze.py:153`, not by reaching into `song` inside `song_row`.
- `graph/curves-manifest.json` must never collide with a code: codes are exactly 10 alphanumerics, the name has a hyphen and a dot, and `_send_graph` rejects a non-alphanumeric stem anyway.
- The curve JSON is published for every code in the sheets, which excludes drums (`analyze.py:126`), so `curves_bytes` never sees a `hand_mask` stream; section 00's lookup guard is what keeps a hand-typed `...XD` request at 404 rather than a traceback.
- The curve fingerprint includes `repr(entry_difficulty(entry))`, so a calibration change in `functions/formula.py` rewrites every JSON (seconds) as well as every PNG (24 minutes); that is correct, the `head` numbers changed.
- `publish --force` now re-renders PNGs and rewrites JSON; the JSON rewrite is cheap and `write_if_changed` keeps mtimes when bytes match, so `--force` still uploads only what changed.
- The two example spreadsheets under `metrics/` predate `SongKey`; do not regenerate them for this section. If they are ever regenerated, `git add -f` the new pair and remove the old in the same commit, as CLAUDE.md says.
