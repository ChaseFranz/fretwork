## Design

**Renderer: `web/markdown.py`, stdlib only, allow-list, raises `MarkdownError` on anything else.** Two passes. `parse(text) -> list[Block]` classifies lines into blocks; `render(blocks, shift=0) -> str` emits HTML. Every character of prose goes through `html.escape`; the only markup emitted is what the renderer builds. `$$` fences are classified first, and lines inside a math block are handed to the typesetter untouched, so the refuse rules below never see a formula line (a future formula that starts with `-` or is indented four spaces must not be refused as a list or as code). Block rules, in the order tried per line outside a math block:

| Line starts with | Block | Rule |
|---|---|---|
| `#`, `##`, `###`, `####` then a space | heading | text after the marker, `rstrip()`ed (line 73); `#####` or deeper raises |
| `$$` alone | display math | lines until the closing `$$`, joined with `\n`, typeset to MathML; an unclosed block raises |
| `>` | blockquote | consecutive `>` lines; a bare `>` splits paragraphs inside the quote; a nested `> >` raises |
| `\|` | table | consecutive `\|` lines; row 2 must be an alignment row (`:?-+:?` per cell) or it raises; every row must have the header's cell count or it raises; alignment `---:` right, `:---:` centre, else left |
| blank | separator | ends the current paragraph |
| anything else | paragraph | consecutive non-blank lines joined with a space |

Before classification, a line outside a math block matching any of these raises with the line number: `^\s*([-*+]|\d+\.)\s` (list), `^```` (fenced code), `^    ` or a tab (indented code), `^---+\s*$` or `^===+\s*$` (rule or setext underline), `^<` (HTML block). Inline rules, applied in this order on the escaped text with placeholders so they cannot nest wrongly: code spans `` `...` `` (contents verbatim, escaped), inline math `$X$` (one identifier, `[A-Za-z]+`, rendered `<math><mi>X</mi></math>`; anything else between single dollars raises), bold `**...**`, italic `*...*` where the opening `*` is followed by a non-space and the closing preceded by one. The leftover rule, run after those: any remaining `[...](...)` (link), `![` (image), `<[a-zA-Z/]` (inline HTML), `` ` ``, `**` or `$` raises; a remaining single `*` raises when it is immediately followed by a non-space character (an opener that never closed) and is literal text when it has whitespace on both sides, so line 75's ` * ` renders as an asterisk and `raw N * V` is a must-pass case. Underscore emphasis is not a rule: the only underscores are inside code spans and the CalcTier header cells, and both stay literal.

Every block tuple carries the line number it starts on, and every `MarkdownError` raised by `render` or the typesetter names it: the message is `line <n>: <what>`. `parse` takes text, not a path, so the file name is prefixed by the caller (`methodology.load` and the `__main__`, as `f"{path.name}: {err}"`).

**Headings get ids.** `slug = re.sub(r'[^a-z0-9]+', '-', text.lower()).strip('-')` over the raw inline text (so backticks and underscores become hyphens), deduplicated with `-2`, `-3`. So `#the-difficulty-formula`, `#remapdiff-0-6-calibration` and `#calctier-calibration` are stable anchors a later section (02's graph heading, 06's readout) can link to. `shift` moves every heading down that many levels and leaves the ids alone; a level past 6 raises, which is unreachable at `shift=1` on a file whose deepest heading is h4.

**Display math becomes MathML, not an image and not raw LaTeX.** MathML Core has shipped in Chrome since 109 (January 2023) and in Firefox and Safari for years. An engine without it shows the tokens in reading order, so a fraction reads as its numerator followed by its denominator; accepted, since no current engine lacks it. The typesetter `_math(latex) -> str` is a recursive descent over an allow-list of tokens: letters run into one `<mi>` (so `CoV` and `CV` are one identifier each, upright, as the prose writes them); digits with `.` into `<mn>`; `= + - , /` into `<mo>` (`-` as U+2212; not used today, allowed so a leading minus is a formula and not a list); `(` `)` open and close an `<mrow>` with the fence as `<mo>`; `\Big[` and `\Big]` likewise with `stretchy="true"`; `_` and `^` take the previous node as base and the next atom or `{...}` group as script (`<msub>`, `<msup>`); `\frac{a}{b}` is `<mfrac>`; `\sqrt{...}` is `<msqrt>`; `\mathrm{med}` is `<mi mathvariant="normal">med</mi>`; `\varepsilon` and `\sigma` are `<mi>ε</mi>` and `<mi>σ</mi>`; `\cdot` is `<mo>⋅</mo>` (U+22C5); `\,` is `<mspace width="0.17em"/>`; `\qquad` is `<mspace width="2em"/>`; newlines and spaces are skipped. Any other `\command`, any other character, an unbalanced brace, or a script with nothing before it raises `MarkdownError` naming the block's line. Output is `<div class="eq"><math display="block"><mrow>...</mrow></math></div>` for blocks (the wrapper is the overflow container, the same role `.tbl` plays for tables) and `<math><mi>N</mi></math>` inline.

Rejected: KaTeX or MathJax from a CDN (the page must not contact a CDN at view time, CLAUDE.md); matplotlib mathtext rendered to SVG (matplotlib stays off `web/`'s import path, and an image of an equation is not text); a `<pre>` of the LaTeX source (unreadable to the audience the page exists for); a dictionary of the seven formulas as hand-written HTML keyed on the LaTeX string (silently stale on a whitespace edit, and a second copy of the source).

**The check lives in `web/methodology.py`, not `functions/`.** It consumes the parser's table blocks, and nothing in `functions/` imports `web/`; the reverse is normal. `load()` reads `Methodology.md` (repo root, resolved from `__file__`, the same way `assets.STATIC_DIR` is), parses it, runs `check_tables(blocks)`, and returns the blocks. `render_methodology()` in `web/page.py` calls `load()`, so the check runs on every serve start and every publish. `python -m web.methodology` runs the check alone and prints one line, for section 04's CI and for a maintainer merging upstream.

## Data and interfaces

**`web/markdown.py`**

```python
class MarkdownError(ValueError): ...          # message: "line <n>: <what>"
def parse(text) -> list[tuple]                # blocks, see below
def render(blocks, shift=0) -> str            # HTML fragment, one block per line
def to_html(text, shift=0) -> str             # render(parse(text), shift)
```

Block tuples, each ending with the 1-based line it starts on: `('heading', level:int, text:str, slug:str, line)`, `('paragraph', text, line)`, `('quote', [text, ...], line)` (one entry per paragraph inside the quote), `('math', latex, line)`, `('table', header:list[str], align:list[str], rows:list[list[str]], line)` with `align` values `'l'`, `'r'`, `'c'`. Texts are raw markdown inline text; `render` applies the inline rules. `render` joins blocks with `\n`, one block per line, so `grep -c` over an opening tag counts blocks. `python -m web.markdown <file.md> [--shift N]` prints `<meta charset="utf-8">` on its first line (so the fragment opens correctly from disk; `page.py` never sees that line) followed by the fragment, or prints `<file>: line <n>: <what>` and exits 1.

HTML emitted, one element per block: `<h1 id="slug">` to `<h6 id="slug">` (level plus `shift`); `<p>`; `<blockquote><p>..</p>..</blockquote>`; `<div class="eq"><math display="block">..</math></div>`; `<div class="tbl"><table><thead><tr><th class="r">..</th></tr></thead><tbody><tr><td class="r">..</td></tr></tbody></table></div>` (class omitted for left, `c` for centre). Inline: `<code>`, `<strong>`, `<em>`, `<math><mi>N</mi></math>`.

**`web/methodology.py`**

```python
MD_PATH = pathlib.Path(__file__).resolve().parent.parent / 'Methodology.md'
class MethodologyDrift(ValueError): ...       # message names the table, the row and both values
def load(path=MD_PATH) -> list[tuple]         # parse + check_tables; a MarkdownError is re-raised as "<name>: line <n>: <what>"
def check_tables(blocks) -> None              # rules 1 to 5 above
```

`python -m web.methodology` prints `Methodology.md: tables match formula.py (3 remap groups, CalcTier 7.6 / 0.44)` and exits 0, or the drift or markdown message and exits 1.

## Risks and gotchas

- The renderer is an allow-list. The first upstream edit that adds a bullet list, a link or a fenced block fails publish with the line number; the fix is to extend `web/markdown.py` with that construct, deliberately, and add the synthetic case to `tests/test_methodology.py`. Do not loosen the refuse rules to "render as text".
- A new `\command` in a formula fails the same way. The typesetter's token table is the whole LaTeX it understands; add to it rather than falling back to raw text.
- Multi-letter identifiers render upright in MathML (`CoV`, `CV`, `med`), which matches the prose but not what LaTeX would do (italic letters run together). Accept it; the alternative, one `<mi>` per letter, renders `CoV` as three italic letters and reads worse.
- `check_tables` compares floats exactly. That is correct while the markdown prints what the code holds; a table that rounds a code value (`13.75` printed as `13.8`) is drift and should fail. Do not add a tolerance.
- Rule 4 assumes one shared `BASE_D` / `LN_INC` pair, which `formula.py:60-64` says is the current state and may change. When it does, the failure message points at this rule, and the fix is a per-group comparison, not a skip.
- `page.fill` today checks the filled page for `__X__` tokens (`page.py:37-40`); `Methodology.md` has no double-underscore token (checked), but section 00's change to check the template instead is what makes rendering an arbitrary document safe. Land 00 first.
- `labels.py` gains an import of `functions.formula`. `formula` imports only `math`, so the import graph stays acyclic; do not make `formula` import `labels`.
- `UI['methodology']` changes `index.html` through the island; `METHODOLOGY_SOURCE` deliberately does not. A reader of a dry run in step 3 should expect two uploads, not one.
- The Tampermonkey userscript prototype reads `#fw-boot`, `#modal .mhead`, the modal's `aria-label`, the row column names and the `?q=&code=` link form; this section changes none of them (the `.more` line and the footer are not hooked), and the island only gains one `UI` string.
- Upstream prose is rendered as written, typos included ("CoV approximate", "kinda"). This fork does not edit `Methodology.md`; a correction goes upstream as a fork PR from a branch off `upstream/main`, per CLAUDE.md.
- The footer count in 04's `test.js` is computed, not typed; the `+ 2` for request and about becomes `+ 3` in step 4 and the suite must change in the same commit, and again to `+ 4` when 03's changelog link lands. Find the methodology anchor by `href`, never by position.
- If 03 lands after this section, its step 4 must not recreate `doc.html` or `render_doc`; it adds `changelog.html` to `DOC_PAGES`, the footer and the allow-lists and moves on. If 03 lands first, this section's `doc.html` change is the CSS block alone.
