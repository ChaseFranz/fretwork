# 06. Client-side graphs and compare view

**Status:** Ready after 05

**Effort:** L, dominated by `web/static/js/graph.js` (the canvas renderer, its hover and keyboard readout, the compare legend and the PNG export are one module that must be right on a 390 px phone and a 4K monitor alike) and the two page suites that prove it; the Python side is a code-list change in publish and one boot key.

**Depends on:** 05 (data-model-v2: `graph/<code>.json` with its `head` object is published and served, `state.data` holds every loaded sheet, `loadSheet`, `SHEET_OF_CODE` and the `fw:sheet` event exist, and the JS is one bundle so a new module is free). Benefits from 04 (the suites named under Verification; until it lands the manual checks in each step are the gate), 07 (the `Compare all levels` button this section renders when `song.js` exists), 02, 10 and 13 (each adds to the heading this section keeps). Interfaces below follow the final text of sections 05 and 07, not their drafts.

## Goal

Draw every chart's graph in the browser from `graph/<code>.json`, reproducing what `functions/plot.py` draws today, and stop publishing 11,903 PNGs. Add what a picture cannot do: a readout of the values under the cursor (mouse, touch and keyboard), an overlay of two or three charts chosen by a picker or from the table, a shareable `?code=A&vs=B,C` link, and "Save as PNG" for sharing. Keep exactly one matplotlib PNG, the social preview `page.OG_IMAGE`, so link previews keep working.

## Why

- `site/Local/graph/` is 2,188,837,822 bytes for 11,904 PNGs (median 182,063 bytes, TTFAF `10145439XG.png` 297,089); the curve JSON for the same charts is 47,613,377 bytes (4,004 for `72933816XG`, 670 gzipped; 8,474 for TTFAF, 1,704 gzipped; section 05's measurement). A phone viewer downloads 4 to 9 KB per graph, under 2 KB gzipped, instead of 180 to 300 KB.
- A full PNG re-render is 0.12 s per chart, about 24 minutes, and any edit to `config.RENDER_THEMES` or a `song.ini` retitle triggers it (`web/bundle.py:69-81` hashes both at `:79` and `:76`). The JSON's fingerprint (section 05) covers the notes, the Expert notes, `source_format` and the difficulty block and never the theme or the meta, so a colour change becomes a JS change and no graph is rewritten.
- The PNG cannot say what the value at 2:41 is, cannot put Hard beside Expert, and is unlabelled to a screen reader beyond its alt text. All three are why people open a graph.
- The `graph/` sync uploads and deletes with `--delete` (`deploy.py:188-189`); once publish's PNG code list is the one preview chart (Design 9), the prune rules already in `web/bundle.py` remove the 11,903 files without a hand-written cleanup.

## Design

**1. One renderer, fed by the same profile.** `web/static/js/graph.js` (new) draws onto a `<canvas>` from the curve JSON and the row. It re-smooths in the browser with the algorithm above in doubles (`Math.exp(-step / tau)`, forward then backward), which section 05 chose so that a smoothing change never re-publishes 11,904 files. Appearance comes from `boot.render`, built in `web/boot.py` by the same two-dict merge `plot.resolve_profile` does, restricted to the keys a canvas can use; a Python test asserts the boot copy equals `plot.resolve_profile()` key for key, which is the drift guard for an upstream file this fork does not edit. The legend and axis strings live in `labels.UI` and a second assertion greps `functions/plot.py` for each literal. Rejected: SVG paths, because 18,358-point paths in three series plus a fill is a 200 KB DOM per open and hover hit-testing is no easier; WebGL, because nothing here needs it; keeping `<img>` with the PNG as a fallback, because the JSON has been live since section 05's deploy and two code paths is the bug.

**2. The picture matches the PNG, except where the PNG was working around matplotlib.** Same z-order, same dotted and solid roles, same fill, same grid, same y head-room, same `m:ss` axis, same legend text, same two header lines. Deviations, each deliberate: the title and artist wrap instead of ellipsising at 44 characters (the PNG's limits exist to keep image widths equal); the level line prints the row's `Type` (`Lead`) rather than `instruments.DISPLAY_NAMES` (`Guitar`) so it agrees with the table; the difficulty words use `labels.COLUMN_LABELS` (`Difficulty (D)`, `Original Tier`, `Remap Tier`, `Calc Tier`) rather than the PNG's `D` / `diff` / `remap bin` / `calc tier`, again to agree with the table; the file format comes from `head.source` as `.mid file` / `.chart file` (`UI.graph_source`); and missing values show `MISS_TEXT` where the PNG prints `-` or `-1`. X ticks are chosen from 5, 10, 15, 30, 60, 120, 300 and 600 s, the smallest step giving at most 10 ticks, or 600 s when none does (no chart is longer than 4,589 s today), rather than `MaxNLocator`'s decimal steps: `2:30` reads better than `2:05` on a time axis.

**3. Readout.** The cursor is a time, not an index, because compare mode has no single `n`: `t_ms = clamp((x - left) / plotWidth, 0, 1) * xMax_ms`, where `xMax_ms = max over charts of (n - 1) * step`; per chart `i = Math.round(t_ms / step)`, and a chart with `i >= n` contributes `MISS_TEXT` to the readout and no dot. Moving a pointer over the plot sets `t_ms`, draws a vertical hairline in `muted_text_color` with a dot on each series, and writes one line under the canvas: `m:ss`, `~D`, notes/s, changes/s at 2 dp. The plot is painted once per size into an offscreen canvas; a pointer move or key press blits it and draws only the hairline, dots and readout, so the per-frame cost is independent of `n`. The readout is a DOM element, not text on the canvas, so it works for touch (no hover) and for screen readers: it carries `aria-live="polite"` for keyboard-driven moves and is switched to `aria-live="off"` for the duration of a pointer move, so a mouse crossing the plot does not narrate every pixel. The canvas has `tabindex="0"`, `role="application"`, `aria-roledescription="difficulty graph"`, `aria-label` = `UI.graph_alt` and `aria-describedby` pointing at the readout; Left and Right move `t_ms` by `step` (250 ms), Shift with them by `40 * step` (10 s), Home and End jump to 0 and `xMax_ms`. The cursor stays where it was when the pointer leaves, so a keyboard user's position is never wiped by a stray mouse. Rejected: `role="img"`, because screen readers treat it as a static picture and some enter browse mode on it, so the arrow keys never reach the page.

**4. Sizing.** The canvas is `width = card content width` CSS px, `height = round(min(max(width * 7 / 16, 220), innerHeight * 0.55))`, backing store `width * devicePixelRatio` with `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`, redrawn on `resize` through one `requestAnimationFrame`. Under 640 px the modal padding drops from 24 to 8 px and the card's to 8 px with no border, so a 390 px phone gets a 358 px canvas; axis margins are fixed CSS px (left 44, right 10, top 8, bottom 28), so the plot area on a phone is 304 px wide, which fits nine `m:ss` labels at 10 px (each about 26 px, 34 px per slot). Both header lines are `flex-wrap`; the readout wraps to two lines on a phone and is measured in Verification.

**5. Compare.** `state.compare` is up to two extra codes; the graph then draws only `d` per chart (three solid lines with their fills; six dotted lines on top would be unreadable), on a shared y axis and an x axis running to the longest chart, with a legend of `UI.graph_legend` (`{title} - {artist}, {level} {type}`) per chart, each with a remove button. Series colours are the profile's own three in order, `color_d`, `color_nps`, `color_vps`, so no new palette entry is needed; the legend text stays `text_color` with a coloured line sample beside it, and the remove buttons are `--fw-dim`, never a series colour. `openGraph` sets `card.style.background = RENDER.figure_bg`, so the card, the legend and the readout sit on the canvas's own colour and the three swatches measure 3.09 / 3.67 / 4.95 on it; the palette reaches the page only through boot, so this cannot be a CSS constant. The readout shows `~D` of every chart at the cursor (`UI.graph_readout_part` per chart, letters A, B, C following the legend). Removing the primary promotes the first extra to primary. A code in `vs` whose sheet is not loaded draws at once and gets its name later: `openGraph` calls `loadSheet(SHEET_OF_CODE[code.slice(-1).toUpperCase()])` for every code `findRow` cannot find and, in its `.then`, while `state.graph` is still that primary, rebuilds `.mhead`, `.mmeta` and `.legend` in place through the controller's `redraw()`; the canvas never waits on the row. The picker lives in the modal, revealed by a `Compare` button: a search box over `Song Title`, `Artist` and `Code` across every loaded sheet (opening it calls `loadAll()`, free after section 05's idle prefetch), listing at most 12 results as `Title - Artist`, level badge, type, D; with an empty box it lists the other charts of the same song (code prefix `code.slice(0, 8)`, Expert first by `LEVELS`, then sheet order), which is what most comparisons are. Rejected: a second modal for the picker, because two stacked dialogs and two focus traps is worse than one card that grows; comparing more than three, because the legend and readout stop fitting on a phone and three colours is what the profile has.

**6. Pick from the table.** The modal is a full-screen backdrop, so "add from the table" hides it: `state.picking = true`, the modal loses `.on` while `state.graph` and `state.compare` are kept, and a bar above the table says which chart is waiting and how to cancel. If section 07's panel is open, `startPicking()` closes it first and does not reopen it (the panel at `z-index:1055` would cover the table the picker needs; 07's rule). The next row click or Enter adds that code (unless it is already in the set or the set is full, which toasts) and reopens the graph; Escape cancels and reopens the graph unchanged. Filters, search and sheet switches all keep working while picking, which is the point: finding the second chart is what the table is good at. This is the first of the two features beyond the catalogue line and ships after the PNG cleanup (step 8).

**7. Focus trap.** With controls inside the card, `router.js`'s "swallow Tab" becomes a real trap for every dialog: `trapTab(dialog, e)` takes the dialog's focusable descendants that are on screen, wraps from last to first and, with Shift, first to last; an empty list keeps the old `preventDefault`. Section 07 specifies the same function, same module, same selector: one implementation, added by whichever section lands first. Initial focus stays on the dialog element itself. The close button is a sibling after `.mhead`, positioned at the card's top-right corner, so DOM order (and Tab order) is: the heading's links (the report link today; 07's song link, 10's copies links and 13's external links as they land), close, canvas, the legend's remove buttons when present, `Compare`, `Pick from the table`, `Save as PNG`, then the picker input when revealed. The first Tab therefore lands on a heading link, which is what 07's `keys.js` case asserts. The backdrop-close branch changes from "not under `.mhead a`" to "the target is the backdrop itself", since the card now has buttons and inputs. Escape is unchanged here; 07 makes it close one layer at a time.

**8. Save as PNG.** A button renders the same charts into an offscreen canvas at 1920 by 840 CSS px with `dpr = 1` (the figure size `figsize * dpi` before matplotlib's tight bbox crops it to 1908 by 774), draws the two header lines onto the canvas (in the modal they are HTML), and hands the blob to an `<a download>` named by a JS twin of `plot.output_filename`: `<code>_<Artist> - <Name>.png`, with `_vs_<B>[_<C>]` inserted before `.png` in compare mode. A fixed export size means a share from a phone and from a desktop look the same. The second feature beyond the catalogue line; ships last (step 9).

**9. Publish keeps one PNG.** The PNG product's code list becomes `[page.OG_CODE]` when that code is in the sheets, else empty with a warning. Everything else is unchanged: `write_if_changed`, keep-on-failure, "prune only codes the prior manifest recorded", the 200-chart flush and `--force` all apply per product as section 05 left them. Section 05's single loop becomes one pass per product, each over its own code list with its own tqdm bar; the JSON pass is 11,904 codes in seconds, the PNG pass is one. On the first publish after this change the prior `manifest.json` holds 11,904 codes and `fresh` holds one, so `prune()` unlinks 11,903 PNGs locally and the graph sync's `--delete` removes them from the bucket. With an empty list the PNG product resolves nothing, so `prune()`'s zero-resolved rule keeps the prior manifest and every prior PNG (`web/bundle.py:149-154`), and writes `{}` when no manifest existed; `render_graphs` replaces the mismatch message with the social-preview warning in that case, since the empty list is deliberate. Rejected: rendering the OG image with the canvas at publish time, because publish has no browser; dropping the OG image, because `og:image` needs an absolute PNG and section 01 counts on link previews; pruning stale PNGs on an empty list, because the zero-resolved guard is the one rule in `GraphRun` that protects a bucket, and the only header it leaves dirty (`Tiny`) is a test site.

**10. Migration order.** Two deploys. The first ships the page that reads JSON while publish still writes every PNG, so an old tab and a new tab both find their file; the second, at least a day later, ships the publish change that prunes. Deploy order inside each run is section 05's (graph first), so at no moment does a live page name a file the bucket lacks. Pick-from-table and Save-as-PNG land after both deploys and go out with the next release, since the catalogued outcome (2.19 GB gone) must not wait on them.

## Data and interfaces

**Curve JSON** (`graph/<code>.json`): exactly section 05's shape, `{"v":1,"step":250,"window":1000,"tau":2000,"n":960,"head":{"N":..,"V":..,"COV":..,"D":15.8675,"RemapDiff":2,"CalcTier":2,"source":"mid"},"win":[...],"var":[...]}`; the reader rejects `v !== 1`, a non-array `win` or `var`, or lengths that differ from `n`, and shows `UI.render_failed`. Reconstruction, which `graph.js` implements as `smooth(json)` returning `Float64Array`s:

```js
const rate = c => c / (json.window / 1000);
const decay = Math.exp(-json.step / json.tau), gain = 1 - decay;
function ema(xs) { let acc = 0; return xs.map(x => (acc = acc * decay + x * gain)); }
const both = xs => ema(ema(xs.map(rate)).reverse()).reverse();
const nps = both(json.win), vps = both(json.var);
const d = nps.map((v, i) => Math.sqrt(v * vps[i]));   // t_ms = i * json.step
```

Pinned vector, shared by `tests/page/graph.js` and `tests/test_graph_json.py` (`curves.smooth_curves` on the same input, 12 dp): `win = [0,1,3,2,0,4]`, `var = [0,1,2,2,0,3]` give `nps = [0.206319956884, 0.233791139980, 0.249274712958, 0.221722210520, 0.166347919619, 0.113576201083]`, `vps = [0.168201115681, 0.190596834038, 0.200329151998, 0.181904979485, 0.135036063769, 0.090279835296]`, `d = [0.186288075129, 0.211092044157, 0.223465862854, 0.200829216391, 0.149876510106, 0.101260262331]`.

## Risks and gotchas

- `functions/plot.py` and `config.py` are upstream's. Nothing here edits them; the drift guards are the test assertions in step 1. If upstream renames a profile key, `render_profile()` raises `KeyError` at serve or publish time rather than drawing the wrong colour silently; an unknown `mode` falls back to light exactly as `resolve_profile` does, and the hosted site assumes `mode == 'dark'`, which `render_profile()` warns about when it is not.
- `color_d` `#B71FB7` is 3.09:1 on the graph background and 2.86:1 on Bootstrap's body, the same 2.9:1-as-text problem CLAUDE.md's palette note describes. It is used only as a 1.5 px line, a 12% fill and a legend swatch, and only on `figure_bg`. Never use it, or `RENDER.color_nps`, for text; the readout and legend are `text_color`, the remove buttons `--fw-dim`.
- Rollback after step 6 is a full PNG re-render: 24 minutes of publish and a 2.19 GB upload, because `manifest.json` no longer records the 11,903 pruned codes. Step 6 copies `site/Local/graph/manifest.json` to `caches/Local_manifest_pre06.json` first; a rollback restores it before publishing, so only missing files render. That line goes into README section 7's rollback recipe in step 6's docs.
- The row's `Difficulty` equals the PNG's `original_diff` only while no `--diff-mode` write-back has touched the library; after one, the page would print the written tier under the `Original Tier` label. The hosted library has never been written back; if it ever is, carry `original_diff` into `frames.py` as a page-build column first.
- 05's bundler is one scope: `graph.js` must not declare a top-level `draw`, `render`, `heading`, `opener`, `toast`, `hintTimer` or any name another module already declares; keep its helpers inside `mountGraph`'s closure, and run `python -m web.bundler` before the first serve.
- The old Tab handling swallowed every Tab; the trap must keep doing so when the focusable list is empty (a modal in its `rendering` state), or Tab escapes to the table behind the backdrop.
- `state.compare` must be cleared on a plain close but kept through picking, or Escape from picking reopens an empty comparison. `closeGraph` takes the `state.picking` check for that reason.
- The picker search runs over every loaded sheet on each keystroke: 11,904 rows, three string columns, well under a millisecond, so no debounce; but `loadAll()` on a cold picker open can take a second on a slow connection, and the results list must show `compare_loading` rather than `compare_none` until every sheet has settled.
- A code in `vs` for a sheet not yet loaded has curves before it has a name: the legend prints the code and line 2 prints `head` values until the `loadSheet` promise in `openGraph` resolves and `redraw()` rebuilds the heading; the redraw must check `state.graph` is still that primary, or a graph closed and reopened in the meantime gets the wrong heading.
- `graph/*.json` is cached a week (`CACHE_GRAPHS`); a chart whose notes changed can show a stale curve for up to a week after a deploy, exactly as its PNG could. The invalidation clears the edge, not browsers.
- Old tabs across step 7's deploy: a viewer holding the pre-step-5 page for a day or more sees `render_failed` on every click until reload. The day between deploys is what makes this rare; do not shorten it.
- The Tiny header (and any library without `10145439XG`) publishes no PNG and never prunes old ones, and `deploy.verify()` then skips the `graph/*.png` glob. Fine for a test site; `rm site/Tiny/graph/*.png` by hand if the space matters. The hosted header is Local, which has it.
- `plot.output_filename` strips non-ASCII, so the JS twin also does; a title that is entirely non-ASCII downloads as `<code>_unknown - unknown.png`, as `render.py` would name it.
- Two LRU caches now exist in the page (curves here, sheets in section 05); the curves one is capped at 100 entries, about 2.3 MB of `Float64Array`s at the 954-sample mean and 4.4 MB if every entry were the 18,358-sample maximum; the sheets one is bounded by the number of sheets.
- `exportPng` renders synchronously at 1920 by 840 with up to three 18,358-point series: tens of milliseconds, but do it on the click, not on open.
- The close button is positioned, not flowed, so whatever 07, 10 and 13 append to `.mhead` cannot push it onto a second line; `.mhead`'s 28 px right padding is what keeps their links from sliding under it. Re-measure at 390 px after any of them lands.
