## Goal

A committed `packs.toml` at the repo root that names every pack in the song library (name, folder, source URL, date added, notes) and carries a hand-written list of site changes. Publish reads it, counts each pack's songs and charts from the cache and the spreadsheet, joins an `Added` column onto every row at page-build time, and writes `changelog.html`: packs newest first, each with its date, a link to where it is published, its counts and notes, interleaved with the site changes. The strapline "Updated 7 September 2026  -  11,904 charts" becomes a link to that page. Section 09's ingestion tool appends to the same file through this section's writer, and both entry points can be pointed at another registry with `--packs`.

## Why

- Nothing on the site says what is in it or when it arrived. `Release` is the song.ini `icon` mapped through `sources/*.txt` (`parsers/ini_parser.py:108-114`): three CSC folders collapse to one `Custom Songs Central` and the 4th-quarter folder splits across `Custom` and `Custom Songs Central` (measured on the newest cache), so `Release` cannot answer "which pack" and carries no date at all.
- The song-pack issue form (`.github/ISSUE_TEMPLATE/song-pack.yml:53`) asks the requester to check "the site's Source column" before filing. A page listing every pack by name and source is the thing that check needs.
- The pack folders exist only as `song_path` prefixes in the cache (`functions/cache.py` docstring; `build.py:104-109`). A registry keyed on that folder is the one exact join available today, and section 09 needs a file to append to.
- A `?f.Added=2026-09-07` link is a shareable "what came in this update" view through the existing URL grammar (`web/static/js/url.js:8-9,23-26`) with no new JS.

## Design

**1. One file, two tables.** `packs.toml` at the repo root holds `[[pack]]` entries and `[[change]]` entries. The site changes go in the same file rather than in `labels.py` because they are dated history, not interface wording: one file, one date type, one render loop, and section 09 appends a pack while a person appends a change with the same editor. Rejected: YAML, because PyYAML is not in `requirements.txt` and the web layer adds no dependencies; JSON, because it has no comments and the file is hand-edited; a `[[pack]]` per `Release` label, because `Release` is not the pack (see Why).

**2. Folder is the key, counts are never stored.** A pack's `folder` is the first path component of a song's path under the library root. In a library with no pack level (Tiny, upstream's layout) that component is the song folder itself, which the registry will not name, so serve warns and publish refuses (design 4). Songs per pack are the cache songs under that folder; charts per pack on the changelog are the sheet codes (`frames.codes_in`) whose song is under that folder, so the count is what the site lists, whatever `XLSX_LEVELS` says. Both are computed at page-build time and printed; the file never carries a number that can go stale. Rejected: storing `songs` in the file as the issue form does, because it drifts on the first re-download.

**3. The library root.** `packs.library_root(cache)`: an absolute `search_path` is used as stored; a relative one (the case on this box) is recovered as `os.path.commonpath` of every `song_path`, walked up until its name equals the last component of `os.path.normpath(search_path)`, so publish from any working directory finds the same root. A one-pack library's commonpath is the pack folder itself; the walk-up stops one level above it, at the directory named `songs`. A stored relative path whose last component never appears on the walk (a renamed `songs/`) raises rather than guessing. A stored `.` or `..` has no usable last component (`pathlib.Path(os.path.normpath('.')).name` is `''`, and the cwd's name at build time is unknowable), so the commonpath is used directly and a warning says so; a one-pack library built with `.` would be misread, and the fix is to build with a named path. Rejected: `Path(search_path).resolve()`, which resolves against the publish-time cwd and silently matches nothing from another directory.

**4. Unregistered and missing folders fail publish and warn serve.** The changelog's promise is that every chart on the site belongs to a listed pack. `resolve()` reports three lists and raises for none of them: `unregistered` (a folder in the cache with songs beneath it that no `[[pack]]` names), `missing` (a registered folder with no songs in the cache: a typo, or a registry for a different library), and `loose` (a top-level folder that is itself a song folder, the one-component case of design 2). Publish exits listing whichever is non-empty, before anything is written. Serve prints all three as warnings and continues, with `Added` null for the rows concerned, so a header whose library is not `songs/` (Tiny, the WSL Clone Hero build) still serves. `loose` gets its own heading and the text "move these into a pack folder", because registering a song as a pack is not an answer. The registry is one file and caches are per header, which is why the rules must not be symmetric: publish is for the one library the site is built from, serve is for looking at any of them. Rejected: an `--allow-unregistered` flag, because section 09 appends the entry before it builds, so the normal path never needs one; raising on `missing` in `resolve()` itself, because that made serve unusable for every header but Local.

**5. `Added` is a page-build column.** `frames.with_added(sheets, added_by_code)` maps `df['Code']` through a `{code: 'YYYY-MM-DD'}` dict onto each sheet before serialisation, so the column lands wherever rows land: the boot island today, section 05's `data/<slug>.<hash8>.json` after it. It is not in `analyze.COLUMN_ORDER`, so the xlsx and the committed examples are untouched. It is an ISO string, not a number: the page's numeric detection would give a number a range box but print it as a number, and a `Date` type does not survive JSON. So the filter is a checklist of dates (never more than the number of packs, and a search box appears past 12, `dropdown_view.js:46`), the sort is `localeCompare`, chronological, and the shareable form is `?f.Added=2026-09-07`. The one JS change is `distinct()` ordering with `Number()` instead of `parseFloat()`, so a date list sorts by string. Measured effect on `metrics/Local_metrics_09072026-2031.xlsx` with both functions emulated: numeric columns are unchanged, since their keys are `String(number)` and `Number()` parses those identically; values a person reads as text now list alphabetically, which moves 32 Song Title positions on Guitar and 19 on Bass (`18 And Life` now before `2 Minutes To Midnight`, which `parseFloat` read as 2), 8 Artist positions on Guitar and 7 on Bass (`+44` before `+TEK`), and every song's four level codes (3,440 positions on Guitar, 2,612 on Bass, 134 on Keys: `parseFloat` stopped at the level letter, so a song's E/M/H/X shared one key and sat in row order; now they list E, H, M, X). Every move is to the order a reader expects, and section 04 gains a case that pins it. Rejected: an integer days-since-epoch column for a range box, because it would print as `20703`; a `Pack` name column, because it duplicates what `Release` mostly says and the brief scopes this section to `Added`.

**6. Serve gets the cache at startup when there is one.** The join needs `cache['codes']` and `cache['search_path']`, and a pickle is all-or-nothing; measured 0.2 s against 0.79 s for `pd.read_excel`, so laziness buys nothing. `serve.serve()` calls `renderer.cache()` inside a `try`, passes the result to the join, and on `FileNotFoundError` serves the page without the `Added` column and without a changelog, printing one banner line. `GraphRenderer.cache()` memoises, so the graph path reuses the same object. CLAUDE.md's "loaded lazily only when a graph is clicked" sentence is amended to "loaded at startup when present, for the pack join; a graph click reuses it". Rejected: a sidecar `caches/<header>_codes_<ts>.json` written by build, which is a new output kind and a new pairing rule for 0.2 s.

**7. One template for the two document pages.** `web/static/about.html` becomes `web/static/doc.html`, rendered by `page.render_doc(name, title, body)` for both `about.html` and `changelog.html`. Same self-contained CSS, same placeholders, plus `__LINKS__` now leads with the site's other document pages before `FOOTER_LINKS`. Section 12's `methodology.html` has its own template, `web/static/methodology.html`, because its content needs a 72ch column, table, blockquote and math rules and a `__SOURCE__` line; it is not on `doc.html`, and if it is later folded onto it, that is a change to 12, not to this section. Rejected: a second copy of the template for the changelog, because two copies of the same 14 CSS rules drift.

**8. Changelog layout.** Grouped by date, newest first: an `<h2>` per date in the strapline's own format (`7 September 2026`), then one `<p class="item">` per item on that date, site changes before packs, packs alphabetical. A pack item is the name (an anchor when `source` is `http(s)`), its counts, then its notes through `rich_text()`. Each date heading is an anchor to `./?f.Added=YYYY-MM-DD&f.Level=Expert`, the table filtered to that update, Expert only, official and custom, since a custom pack's update would otherwise show nothing (the site itself opens on Expert and Official, `main.js:58-59`; the link deliberately drops Official). An intro line and a totals line (`26 packs, 1,758 songs, 11,904 charts`) sit above the list. Static, no scripts, like `about.html`.

**9. The strapline date stays the build timestamp.** A pack's `added` is when it entered the library; a change's `date` is when the site changed; the strapline says when every number on the page was computed, which is the only date that certifies all of them at once, and it is what README step 7 checks after a deploy. Only its markup changes: `page.strapline(source, linked)` wraps the escaped text in `<a href="changelog.html">` when the changelog exists, and `main.js` copies `#src`'s `innerHTML` into the footer's `#src2`, so the footer copy is a link exactly when the header copy is. Under serve with no cache the text is plain and nothing links to a page that is not there. The grep `Updated [^"]*charts` still matches, since no quote falls between the two words. Rejected: an unconditional anchor in the template, because a serve without a cache would link to the 404 page.

**10. Preferences.** `Added` joins `DEFAULT_HIDDEN`. If this lands after 05, bump `labels.PREFS_VERSION`; if before, 05's first bump covers it, and until then a returning visitor sees a ten-character column at the far right of the table, which is accepted rather than adding a migration this section would have to remove.

## Data and interfaces

**`packs.toml`** (repo root, committed, UTF-8, comments allowed):

```toml
# packs.toml - every pack in the song library and every change to the site.
# One [[pack]] per top-level folder under the search path; counts are computed
# from the cache at publish time and never written here. Dates are bare TOML
# dates (no quotes, no time). tools/ingest_pack.py appends [[pack]] blocks
# through functions/packs.py; [[change]] blocks are written by hand. Publish
# refuses a cache folder this file does not name, and a folder named here that
# the cache does not have.

[[pack]]
name = "Guitar Hero III (Individual Songs)"   # as the changelog prints it
folder = "Guitar Hero III (Individual Songs)" # the directory under songs/
source = ""                                    # http(s) URL, or "" for none
added = 2026-09-07                             # TOML date
notes = ""                                     # free text, [text](url) allowed

[[change]]
date = 2026-09-07
text = "First publish: Guitar, Bass and Keys sheets, a graph for every chart, shareable views."
```

Rules enforced by the loader, each raising `PacksError` with the entry's name or index in the message: `name`, `folder`, `added` required; `source` and `notes` default `""`; `folder` and `name` unique; `folder` a single path component (no `/`, `\`, not `.` or `..`, not empty); `added` and `date` must satisfy `type(v) is datetime.date` (a quoted string is an error, and so is a local date-time such as `2026-09-07T10:00:00`, which `tomllib` reads as a `datetime.datetime` and the changelog would group apart from the bare date); `source` must be `""` or start with `http://` or `https://`; no string value may contain a character of Unicode category `Cc` (U+0000 to U+001F, U+007F to U+009F: newline, tab and DEL included), which is the same rule the writer enforces on its input; unknown keys are an error. Order in the file is irrelevant; the renderer sorts.

**`functions/packs.py`** (new, stdlib only: `tomllib`, `dataclasses`, `datetime`, `os`, `pathlib`, `unicodedata`; no pandas, no `web/` import, so the pipeline side stays importable without the viewer):

- `PACKS_FILE = pathlib.Path(__file__).resolve().parent.parent / 'packs.toml'`
- `class PacksError(ValueError)`
- `@dataclass(frozen=True) Pack(name, folder, source, added: datetime.date, notes)`; `Change(date: datetime.date, text)`; `Registry(packs: tuple[Pack], changes: tuple[Change], path: pathlib.Path)` with a `by_folder` property.
- `load(path=PACKS_FILE) -> Registry`, raising `PacksError` as above, and `FileNotFoundError` as is when the file is absent.
- `library_root(cache) -> pathlib.Path` (design 3); `PacksError` when no root matches.
- `folder_of_songs(cache, root) -> {song_path: folder}` (first component under the root).
- `resolve(cache, registry) -> Resolved(registry, library_root, added_by_code: {code: 'YYYY-MM-DD'}, folder_by_code: {code: folder}, songs_by_folder: {folder: int}, unregistered: tuple[folder], missing: tuple[folder], loose: tuple[folder])`, all three tuples sorted; raises only for `library_root`. `unregistered` holds folders with at least one song at two or more components beneath the root; `loose` holds folders that are themselves a `song_path`; `missing` holds registered folders with zero songs. A code under an unregistered or loose folder is absent from `added_by_code` (so its cell is null) and present in `folder_by_code`.
- `report(resolved) -> str`: the three lists as lines, `packs: 26 registered folders with no songs in this cache` / `packs: 6 loose song folders directly under the library root (move these into a pack folder)` / `packs: 2 folders not registered: ...`, empty when all three are empty. Publish prints it and exits; serve prints it and continues.
- `tally(resolved, codes) -> {folder: (songs, charts)}` where `charts` counts the given `codes` whose folder matches; a registered folder absent from `codes` tallies `(songs, 0)`. `render_changelog` passes `frames.codes_in(sheets)`; the `__main__` passes the cache's 5-fret codes.
- `scored_codes(cache) -> list[str]`: `[code for song in cache['songs'].values() for inst, levels in song['codes'].items() if inst in instruments.SCORED_INSTRUMENTS for code in levels.values()]`, 11,904 on the newest Local cache. `instruments.SCORED_INSTRUMENTS` is a new tuple of the five 5-fret keys (the instruments analyze scores today), which section 11 extends with `drums`; no instrument name is spelled outside `instruments.py` (CLAUDE.md), and section 09's per-pack count uses the same helper.
- `format_string(value) -> str`: raises `PacksError` if `value` contains a `Cc` character; otherwise `'"' + value.replace('\\', '\\\\').replace('"', '\\"') + '"'`. That is a complete TOML basic string: with control characters refused, the only characters TOML requires escaped are the backslash and the quotation mark, and the file is UTF-8 so `é` and a musical-note emoji go in raw. Rejected: `json.dumps`, because `ensure_ascii=True` writes astral characters as surrogate pairs that `tomllib` refuses, and `ensure_ascii=False` leaves DEL raw, which it also refuses (both measured).
- `append_pack(path, pack) -> None` for section 09: reads the file, builds the new text in memory (`\n[[pack]]\n` then `key = value` lines in the order `name, folder, source, added, notes`, strings through `format_string`, the date bare as `YYYY-MM-DD`), writes it to `<path>.tmp` beside the file, runs `load()` on the temporary file (which enforces every rule above, the duplicate `folder` included), then `os.replace(tmp, path)`. On any failure the temporary file is removed and `PacksError` names the entry; `packs.toml` is as it was. Section 09 calls this and nothing else writes the file; 09's own block writer (`PACK_FIELDS`) is replaced by it, and 09 keeps its duplicate-folder refusal by catching `PacksError`.
- `python -m functions.packs [--header NAME] [--cache FILE] [--packs FILE]` loads the cache (newest for the header by mtime, as `GraphRenderer.cache()` does, or `--cache`) and the registry (`--packs`, default `PACKS_FILE`), prints one row per registered folder (`folder`, `songs`, `charts (cache, 5-fret)`, `added`), the totals, then `report()` or `unregistered: none`. It reads no spreadsheet, so `functions/` stays pandas-free; the changelog's chart count is the one from the sheets, and the two differ only when `XLSX_LEVELS` is neither `ALL` nor `EMHX` (Risks). Rejected: an `--xlsx` flag with pandas imported inside `main()`, because the runbook already checks the sheet count on the published page and section 09's summary diff runs before analyze has necessarily finished.

**Column `Added`**: key `Added`, values `'YYYY-MM-DD'` or `null`; `labels.COLUMN_LABELS['Added'] = 'Added'`; `COLUMN_HELP['Added'] = 'When the pack this chart came in was added to the site, from packs.toml.'`; `DISPLAY_ORDER` gains `'Added'` after `'Release'` (the composed order once 08 and 10 have landed is fixed by section 10: `Release`, `Album`, `Year`, `Genre`, `Added`, `Copies`); `DEFAULT_HIDDEN` gains `'Added'`; `MISSING_HELP['Added'] = 'Not registered in packs.toml'`. ## Risks and gotchas

- `library_root` depends on `song_path` being absolute and resolved on the machine that publishes. A cache built on Windows and published from WSL has backslash paths that `pathlib` on Linux does not split; that is already true of the graph renderer's `original_diff` lookup by `song_path`, and the rule stays: build and publish on the same box.
- `os.path.commonpath` of a one-pack library is the pack folder itself; the walk-up stops one level above it, at the directory named `songs`, and a stored relative path whose last component never appears (a renamed `songs/`) raises rather than guessing. A stored `.` cannot be walked and is used as is with a warning (design 3).
- Loose song folders: a `song_path` one component under the root is reported under `loose`, never under `unregistered`, and cannot be registered; the fix is a pack folder, not an entry. Every song of the Tiny cache is one, and so is every song of a library laid out the way upstream's `config.py` assumes.
- The registry is one repo-root file and caches are per header. Publish is for the library the site is built from and refuses any other; serve only warns, so browsing the WSL Clone Hero build prints three warning lines and a blank column, which is the intended behaviour. A second library that must publish uses `--packs` with its own file.
- `frames.codes_in` reads `Code` as `str`; the `map()` in `with_added` must too, or a sheet pandas read as numeric (none today, since the level letter keeps them text) would map nothing.
- The `__main__` counts 5-fret codes from the cache (11,904 today); the changelog counts sheet codes. They differ when analyze ran with `--xlsx-levels` other than `ALL` or `EMHX`, and the changelog's number is the one the site lists.
- `readUrl()` replaces the opening filters when any `f.` param is present (`url.js:58-59`), which is why the changelog's date links carry `&f.Level=Expert` explicitly; without it the link would show Easy through Expert, official and custom.
- The `Number()` change in `distinct()` reorders the Song Title, Artist and Code filter lists (design 5, measured). Every move is towards alphabetical order, and the `order.js` case pins it; a column mixing numeric strings and text would list alphabetically too, which `isNumeric` already treats as text for filtering.
- `Added` is hidden by default but its filter still applies while hidden (documented in CLAUDE.md for `DEFAULT_HIDDEN`), so the changelog's link shows "Clear 2 filters" with one visible filtered header. Section 02 or 07 may want a filter summary; not this section.
- The Tampermonkey userscript (docs-tooling map) reads columns by name from `#fw-boot`, so an appended column moves nothing it reads; it fetches `index.html` daily, which is 154,752 bytes heavier until section 05 moves the rows out.
- Two packs added on the same date are one changelog group and one `?f.Added=` view; that is the intended reading ("this update"), and the pack names inside the group still say which is which.
- A `[[change]]` text goes through `rich_text()`, so a `[text](url)` link works and any HTML is escaped; the same string never reaches `rich()` in the browser, so the two renderers stay in step without a new caller.
- `append_pack` never leaves a broken registry: the new text is checked by `load()` on a temporary file and only then renamed over `packs.toml`. The `Cc` refusal is what makes the writer's escaping complete; relaxing it (to allow tab, say) means re-deriving the escape table against the TOML spec, not just the `tomllib` tests.
- Deleting the `about.html` template while the published `about.html` keeps its name is deliberate; `prune_page` sweeps by published name, so nothing in `site/` is removed by the rename.
- `deploy.verify()` samples `index.html` for `text/html`; `changelog.html` is uploaded by the same pass with the same derived type, so it is covered without a new sample.
- If `practice` is excluded from the library later (open question), removing its folder and its `[[pack]]` in the same commit keeps publish passing; removing only one of them fails it, which is the point.
